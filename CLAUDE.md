# Sentinel

## Project overview

Sentinel is an open-source AI code review GitHub Action.
It runs on pull requests, sends the diff to Claude, and posts (or updates) a review comment with findings.

Stack:

- TypeScript, compiled/bundled with tsup.
- `@anthropic-ai/sdk` for calling Claude.
- `@octokit/rest` for GitHub API access.
- `zod` for validating any data that crosses a system boundary (API responses, action inputs, webhook payloads).
- `vitest` for tests.

## Conventions

- Strict TypeScript. No `any`, ever. Use `unknown` plus narrowing or a Zod schema instead.
- Validate all external data (GitHub API responses, Claude responses, action inputs) with Zod at the boundary. Do not trust unvalidated shapes past that boundary.
- Prompts are not inline strings in source code. They live in `prompts/` as versioned `.md` files and are loaded at runtime.
- Markdown docs (this file, `docs/`, `README.md`): one full sentence per line. Normal Markdown structure (headings, lists, code blocks) is preserved; just don't wrap multiple sentences onto one physical line.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, etc.).
- Never add an AI agent as a co-author on commits.

## Phase 1 scope

Phase 1 is a walking skeleton only. The goal is an end-to-end path from "PR opened" to "comment posted," with no review intelligence yet.

In scope:

- Action scaffold (`action.yml`, workflow, `package.json`, `tsconfig.json`).
- `src/index.ts` entry point.
- `src/github.ts`: fetch a PR diff, post a review comment, and update it idempotently on subsequent runs instead of posting duplicates.
- `src/reviewer.ts`: call Claude with the prompt loaded from `prompts/reviewer.md`.
- `src/context.ts`: token estimation and diff truncation at 50k tokens, with a truncation notice appended when truncation happens.
- `prompts/reviewer.md`: a stub only. The actual review prompt is written by Javier, not generated by the agent.

Out of scope for Phase 1 (do not build yet):

- Actual review logic/prompt content.
- Multi-file diff chunking strategies beyond simple truncation.
- Config file support (e.g. `.sentinel.yml`) for per-repo customization.
- Inline PR comments on specific lines (Phase 1 posts one whole-PR review comment).
- Caching, rate limiting, or retry/backoff logic.
- Any UI, dashboard, or hosted service. This is an Action only.

Do not build ahead of this scope. Confirm with Javier before starting the next phase.
